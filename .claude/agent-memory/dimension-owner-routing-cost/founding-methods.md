# 路由成本维度 — 奠基测量法（2026-08-04）

1. **Description 是路由唯一读的字段**: charter 正文在路由决策发生时还没被读到——正文写得再对也救不了 description 的歧义。最硬的冲突形态: 两份 description 装同一道例题指向不同 owner（cto/architect 的"跨设备会话同步"双答案案）。
2. **路由面常驻账基线**: 23 份 description 共 ~4,289 词, 每个顶层轮次都付, 派不派都付。cto 266 + architect 270 = 536 词曾互相矛盾（持续损失, 比偶发误派更贵）。闲置 agent 的真实持有成本 = 它的 description, 不是 charter。
3. **判别性不来自长度**: 63–74 词的窄 dev description 零歧义; 300+ 词塞满 example 的照样撞车。不设词数目标, 为消歧重写, 长度落哪算哪（P-7）。
4. **三种路由模式的成本结构**: 路由 agent 猜（付 description 常驻 + 判别性决定命中）/ skill 程序化抓取（零猜测, description 可极短——HR 全员即此模式, 本部门自身就是样板）/ cadence 触发（条件写死零判断）。给角色配错模式 = 白付路由面或白丢命中率。
5. **路由命中审计**: 拿一段时期实际任务（memory/git 考古）对照应然归属。未命中三形态: 被上级代做（前任 head 代做结构判断且质量更差——命中损失是准确率损失, 不只是 token）/ 被相邻角色吸走 / 落在无人认领缝里。低活动只有一种读法: 路由缺陷诊断信号, 不是裁撤理由（宪法第 2 条）。
6. **平台可实现性前置**: 声称的派发线若平台不允许（subagent 无 Task/Agent 工具）, 则归属必然漂移到能派发的人——评估归属提案先查可实现性（P-11, ai-researcher 案）。

## 档案

本维度无前任。奠基证据在法官判例库（`pupu-hr-judge/precedents.md` P-1/P-7/P-11）与 2026-08-04 org-rebalance 三镜头材料。
