2026-07-21 CEO 给 COO 线常设授权升格为「业务操盘手」,并提议新建"市场调研团队"。HR (pupu-hr-head) 委托我做 scope 重叠把关(增编场景,不是裁撤)。

**核心裁决(反扩编诚实检验):**
- **不是 growth-ops 的 charter 拉伸能覆盖的。** growth-ops「巡」的分析引擎是 `pupu-growth-analyst` skill,纯 GitHub 自家 repo 中心(gh CLI / 自家 traffic/downloads/community/contributors),零竞品/市场/变现面。扩到外向市场调研=换一整套方法论(web research)+换工具面(WebSearch/WebFetch vs gh)+换认知模式(精确自测快照 vs 定性外向扫描)。这是真能力缺口,不是小拉伸。
- **但需求证据薄。** growth-ops memory 里已证的 P0 是**曝光/放大器缺口**(0 社交 0 社区,见 growth-ops/[[exposure-ceiling-channels]]),不是"看不懂竞品"。没有任何市场调研需求信号浮现。裁撤双证的对偶纪律:增编也要真需求证据,现在证据不足以支撑常设新 agent。
- **建议:** 先用 bounded charter / skill 按需回答具体市场问题(growth-ops 或 ai-researcher 挂载调用),重复需求证实后再毕业成常设 agent;若 CEO 坚持常设,则 scope 收死为纯外向(竞品/市场/变现情报),硬交棒给 growth-ops 出"PuPu 该做什么"。

**三条重叠边界(重叠地图):**
- vs **growth-ops「巡」**: 主要**互补**,一条危险接缝=「下一步方向 / 渠道曝光策略」。切法:巡看镜子(自家健康度回望+PuPu 操作建议 P0/P1/P2),研看窗外(市场竞品前瞻情报)。研出情报喂给巡,巡独家拥有"PuPu 该做什么"。COO 周报归巡。
- vs **pupu-ai-researcher**: 都叫 researcher 但不重叠。ai-researcher=读代码(竞品技术拆解、how it works,Codex 驱动,归 llm-expert)。market-research=读市场(定价/定位/份额/口碑)。规则:读码归研究员,读市场归调研。
- vs **pupu-llm-expert「智」**: 近零重叠。token/成本优化是内部工程成本非对外定价;模型市场趋势属智的模型策略(讲能力非讲市场定位)。

信号1佐证:growth-ops 是**活跃贡献 agent**(2026-07-21 当天改 3 个 memory 文件,非死重),它正是新角色要防重叠的在编对象。
