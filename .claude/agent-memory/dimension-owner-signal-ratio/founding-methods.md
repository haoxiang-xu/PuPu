# 有效信息比例维度 — 已验证测量法（2026-08-04 boilerplate 案）

1. **样板检测禁止假设逐字相同**: 同一 harness memory 模板在 15 份 charter 里有 7 个变体（6 个不同 md5 + 1 份小节标题异构 + 1 份残缺拷贝）。测法: 逐文件与 harness 注入内容 diff, 每份文件有自己的正确答案; 单一 sed/脚本批量处理必然静默丢内容。
2. **计数谓词要先说清**: "带模板"（15）与"带完整模板"（14）是两个不同谓词, 两个都对。报数字前先写谓词。
3. **样板段前后的非样板内容是最不可替代部分**: 模板段之后每份有 ~4 行 agent 专属记忆策略（如擎的 unchain_adapter 子域地图/events_v4 契约语义）——那是该 agent 唯一的记忆策略, 处置样板时它是新形态的主体, 不是陪葬品。目标形态 = 短自定义段（6 份好样本: architect/dev-backend/HR 旧四人）, 不是删空。
4. **信噪比基线（2026-08-04 实测）**: 15 份污染 charter 有效占比仅 26–39%; 净 role content 全组织最厚 1850 词（release-full-test）, 最瘦 704 词。变更提案的信噪比预测以此为标尺。
5. **拆分的信噪比检验（S4 关）**: 若噪音是共享样板, 拆完两份各带一份样板, 占比不升反降——处方是抽公共块不是拆编制。
6. **灰度门（对任何批量 charter 变更）**: 金丝雀 = memory 写入频率最高的 3 个（信号出现最快; 低频角色成功与失败长得一样）; 观察窗 7–10 天; 验收 = `git log --since=<上线日> -- .claude/agent-memory/<agent>/` 非空, 不是 lint 绿。CI lint 须双条: 断言无重复样板 + 断言 harness 注入契约在场且版本已知（只查重复的 lint 在模板消失时保持绿灯）。
7. **对照组要落在被推论的类上**: "删了没事"的证据当时只覆盖低 memory 依赖角色（真正零样板对照组只有 2 个且都是章程上不依赖 memory 的）; 对高依赖角色（擎/智/守）是跨类外推, 结论须显式限定或补观察窗。
