# Context 纯净度维度 — 已验证记账法（2026-08-04 org-rebalance 实战）

1. **Per-call 账只含两项**: charter 净 role content + `MEMORY.md` 索引。memory 目录体积不进账（196KB 目录的常驻索引可能只有 532 词; 目录是按需查阅成本）。
2. **先剥样板再比较**: charter 原始词数排名与净排名可完全反转（案例: 表面最胖的 6 个 dev 剥离 harness 样板后是全组织最瘦, 704–777 词; 表面 1850 词的 release-full-test 才是真最厚）。样板检测法归 signal-assessor, 你直接用它的净值。
3. **内聚度是 isolation 的反向约束**: 拆分线两侧 co-change %（git log 同 commit 率）。阈值判例: 第二人门槛 < 20%; 实测 73–87% ⇒ 沿任何轴切都切断热路径, isolation 反而让每次任务载两份 context。
4. **模型档相关性**: 只报"档位与实测负载相关性缺失"这个可测事实（案例: 最活跃的 4 个已在 fable, 最瘦的 6 个 dev 全 opus）; 无单价证据不报金额。
5. **大 memory ≠ 贵 ≠ 臃肿**: cto 196K/architect 172K 是 ADR/契约类职务产出, 且不进 per-call 账。判"memory 失焦"要看索引聚焦度（signal-assessor 的账）, 不看目录体积。

## 立场纪律

- 成本尺只有拆/减载方向。"便宜到留着无妨"恒真无判别力, 不是本维度的合法结论（P-5）。
- 不编造 token 数字; 每个结论给命令+数字或文件+行号。
