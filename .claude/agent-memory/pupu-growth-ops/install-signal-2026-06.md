PuPu 安装意图（安装包下载）是最强真实增长信号。逐版可验证 delta：

- **v0.1.6**（2026-05-25 发布）：06-09 累计 47 → 06-14 累计 64，5 天 +17（≈3.4/天）；生命周期速率 ≈3.2 dl/天。**历史最高。** 自 06-14 起冻结在 64（用户已迁移到 v0.1.7，老版归零符合一贯模式）。
- **v0.1.7**（2026-06-14 发布）：06-23 累计 21 → 06-26 累计 23，**3 天仅 +2（≈0.67/天）**；12 天生命周期速率 ≈1.9 dl/天。**明显低于 v0.1.6 同龄速率（3.2/天），约为其 60%。** 平台分布反转：linux deb 13 / win 7 / **mac dmg 仅 3**。
- v0.1.5：73；v0.1.4：63。均已归零。

- **v0.1.7（2026-07-05 更新，发布21天）：累计 36（dmg 11 / exe 9 / deb 16）。** 06-26→07-05 的 9 天 +13（≈**1.44/天**),对比前一段(06-23→06-26)的 0.67/天 **速率翻倍、在加速**;生涯速率升到 1.71/天。**平台反转再反转:mac dmg 3→11(9天+8)成为增长引擎**,linux/win 平缓。之前"linux主导mac垫底"的观察本周被推翻——mac 自动更新通道未证实,但 dmg 手动下载确在猛涨。

**判定（2026-06-26 旧）：安装速率出现回归信号。** v0.1.7 dl/天低于前一版,已交 release ops。
**判定（2026-07-05 更新）：回归信号在自我修复。** v0.1.7 起步冷、现速率翻倍追赶,但生涯 1.71/天仍仅为 v0.1.6 当打期(3.2/天)的约一半 → 保留 flag 但降级:根因更像"发布静默/传播不足"而非版本吸量缺陷。已请 release ops 复盘 v0.1.7 发布传播动作。
**可能的良性解释（须证实，勿当定论）：** ① mac 自动更新走 .zip 通道、不增计 .dmg → mac 3 可能被低估；但 v0.1.7 资产里似乎无 mac zip，若确无则 mac 用户只能手动下 dmg、3 就是真低。② Windows NSIS 自动更新会增计 .exe，故 win/linux 数更接近真实新装。release ops 应确认 v0.1.7 的 mac 自动更新通道是否存在。

**平台偏好变化：** v0.1.6 三平台均衡（23/22/19）→ v0.1.7 linux 主导、mac 垫底。发布仍须三平台齐发；mac 通道要单独查。

**Why 这条重要：** CEO 数据优先且最看重「有没有人真在装」。上次此信号是最强正向、支撑「加快发布节奏」；本次它转为最大隐忧，运营建议相应调整为「先查 v0.1.7 为何吸量下降，再谈加节奏」。
**How to apply:** 每次巡船 diff 最近 release 的 download_count 算 dl/天并与上一版同龄对比；当前 v0.1.7 处于回归观察期，下次巡船重点看其速率是否回升、mac 通道是否查清。相关：[[clone-spike-2026-06]]、[[silent-downloader-gap]]。
