## S0 — rich tool result (`content_blocks`)
- **Contract:** a tool result dict MAY carry reserved key `content_blocks: list[block]`. Absent/empty/invalid → legacy behavior byte-identical (zero migration). Block vocab append-only; today `text`/`image`. Image block is FLAT: `{"type":"image","media_type":"image/png","data_b64":...,"width":...,"height":...}` (w/h optional). NOTE this differs from the INPUT-message canonical attachment shape in `providers/native.py` (`{type:image, source:{type:base64, media_type, data}}`) — two different shapes on purpose; tool-result uses the flat `data_b64` one.
- **Builders** (`tools/messages.py`): the contract method is now `build_tool_result_messages` (returns a **list**); legacy `build_tool_result_message` proxies to `[0]` via `_ProviderMessageBuilderBase`. Anthropic surfaces image as native `{type:image,source:{base64}}` INSIDE `tool_result.content` (built directly — `_translate_content_blocks_for_anthropic` does NOT recurse into tool_result blocks). Gemini → `inline_data` parts. OpenAI/Ollama → text placeholder. **OpenAI image回流 is a deliberate llm-expert DECISION POINT** (marked with TODO in code) — the list return shape exists precisely so image can later become a separate user message; do not implement without llm-expert spec (model-visible).
- **Other DECISION POINT for llm-expert:** when `content_blocks` present, business (non-block) fields are DROPPED from the model-visible tool result (only blocks shown) — matches architect contract; flag if llm-expert wants business-fields-as-text.
- **MCP** (`toolkits/mcp.py`): `_parse_call_result` now collects image content blocks into `content_blocks` (was silently dropped). Text-only path refactored into `_parse_success_payload`, byte-identical.
- **Host interception hook (least-invasive choice):** did NOT add a kernel-registered transform (would thread a new arg through Agent→modules→loop = core-interface change = 智+CTO 双签). Instead: `tool_result` events already carry a mutable `deepcopy` of `visible_tool_result` (emit runs AFTER the transcript message is built, so redacting the event copy never corrupts the model transcript). Added host-facing `iter_result_image_blocks()` + `redact_result_image_data()` in `messages.py` — PuPu adapter calls redact in its tool_result callback to strip base64 before SSE. Zero core wiring.
- **execution.py** call sites: the two result-carrying sites (plugin path + main execute) use plural `build_tool_result_messages` + `extend`; error/human-input sites stay on the singular proxy. Coalesce (anthropic block arrays) handles block arrays fine; budget is now image-aware (see 智 review section — text-only budgeting, image preserved).

## S1 — provider-native predefined tool + beta header
- `Tool` gains `provider_native_specs: {provider: spec}` + `required_betas: {provider: [beta]}` (deep-copied, provider-key lowercased), threaded through `from_callable` + decorator re-wrap. `to_provider_json` short-circuits to native spec (deepcopy) when present; else generic. Native spec MUST keep a `name` key or provider_replay `tool_schema_manifest` breaks.
- `Toolkit.required_betas(provider)` aggregates+dedupes (stable order). `providers/anthropic.py` `_collect_required_betas` → sends `extra_headers={"anthropic-beta": ...}` on the existing `messages.stream` call (no beta-namespace switch). Hyperspace shares wire format but not anthropic betas (provider="hyperspace" won't match anthropic-keyed betas).
- **`to_provider_json` bypass paths that must not break native spec (all verified with tests):** exposure `_build_exposed_toolkit` re-registers the SAME Tool object by reference (native spec travels); provider_replay digest/manifest; the 3 provider request builders. Computer tool: `{"type":"computer_20251124","name":"computer","display_width_px":W,"display_height_px":H}` + beta `computer-use-2025-11-24` (architect-provided literals).

## Test mechanism (reusable for any unchain worktree)
- unchain is editable-installed via a PLAIN-PATH `.pth` (`__editable__.unchain-0.2.0.pth` = `<maintree>/src`, compat mode, not a PEP660 finder).
