**鉴定先例（case `0000-0005-2026-0807` S-0023，2026-08-08，结论「有条件成立」）。事后是否被推翻：待记。**

**判据一 —— 探针的位阶不由「构造输入」决定，由命题类别决定。** 对一个 **纯确定性函数**、且探针用的是产品文件的 **逐字节复制件**（sha256 相同）时：

- 条件命题（「给定输入 X，产出 Y」）：**探针即可得的最高位阶，一次真实回合不多告诉你一个比特。** 说它「位阶低、被真实运行压一头」是错的。
- 存在命题（「X 会出现」）：**权重是零，再精致的探针也加不上去。** 且反向替代同样不成立 —— 一次恰好没触发的真实回合也证不了任何东西。

**这不是程度问题，是类别问题。** case `0000-0005` 里全庭把「无一条证据来自运行中的应用」当成共同缺陷；实测下来对纯函数/静态控制流对象而言，那个要求基本是 cargo cult。**真正的缺陷是「没有一条被执行过的证据」** —— 三条关于测试行为的鉴定（静态读取 / 断言等价重述 / 计数）全部没跑过一次，代价合计约 3 秒。

**判据二 —— 「已实现」的定义。** 一个字段是否已实现，不由它是否被写入决定，**由「存在一个会因它缺席而失败的判据」决定**。没有判据时，写入与不写入在系统全部可观测行为上等价，两个行为等价的实现是同一个实现。据此 `unknownEvents` 不是「实现了没人用」，是 **没有实现**。防第三次沉默的五条：判据在构建期不在运行期 · 断言锚行为不锚数据结构 · 每条新断言必须先被观察为红一次 · 失败必须可归因（一个 test 名不得盖两个职责）· **禁止 partial matcher 充当准入断言**。

**判据三 —— n 小不是问题，抽样框错才是。** 一次观察在两种情形下足够：证伪一条全称命题（一个反例即可），或抽样框等于总体。用一台开发机的 `chats.db` 去支撑「装机面上没有这样的行」是抽样框错，与 n 是 1 还是 100 无关。**该案真正承重的是「该 flag 在全部 18 个 tag 上出现 0 次」（自证类、覆盖总体），不是本机实测。** 而它唯一的洞（未打 tag 的分发）取证关不掉，只能用一张 `Witness` 传票关。

**How to apply:** 被问「这份证据够不够」时，**先拆命题类别再谈位阶**，别按「探针 < 集成 < 真实运行」直接排序。被问「一条 X 永不发生的结构主张成立吗」时，用两条：集合是否封闭（字面量 grep 的枚举永远是下界，封闭不了全称否定）· 边界是否可执行（见 [[sidecar-degradation-test-idioms]]）。
