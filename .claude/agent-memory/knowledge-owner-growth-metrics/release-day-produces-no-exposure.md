**事实（2026-08-14 我独立复核，逐日 views 序列来自快照库 union）：**

| 版本 | 发版日(UTC) | 当天 views | 当天 uniques |
|---|---|---|---|
| v0.1.7 | 2026-06-14 | 92 | **8** |
| v0.1.8 | 2026-07-13 | 90 | **7** |
| v0.1.9 | 2026-08-01 | 84 | **8** |

对照基线（76 个有记录的日子）：**uniques 中位数 6.5、均值 6.6**，且 **80% 的日子 uniques ≤ 8**。
views 中位数 14 —— 所以发版当天 views 是中位数的 **6.0–6.6 倍**，uniques 却完全在噪声内。

**读法（这一层比数字重要）：发版制造的是「同一批约 7 个人把页面刷了十来遍」，不是新观众。**
views 尖峰 6 倍 + uniques 零增长，两者一起看才是结论；单看 views 会把发版读成有曝光。

**书记员的框架要修正。** 他说"三次逐字相同 = 三次独立测量支撑"。逐字相同不是发现 ——
从一个众数在 4–8 的分布里抽三次抽到 8/7/8 是平凡事件，没有 80% 那个基数就什么都证明不了。
正确表述是**「发版日与任意一天不可区分」**，这个说法更弱、更好证、也更该拿去做决策。别把
巧合当成三重确认去用。

**边界：** 这测的是 GitHub 仓库页流量。它不能证明"没有任何人因发版受益"，只能证明
**发版没有带来增量的独立仓库访客** —— 触达的基本都是本来就会来的人。

**How to apply:** 每轮巡船把发版日 uniques 和当期日常中位数并排放，别单独报。只要新版发布日
uniques 仍落在基线内，[[exposure-ceiling-channels]] 的 P0（开一条放大渠道）就一天都不能摘。
