**规则：任何"从你的快照库里拉出来"的结论，复核到数字一级，不要只复核方向。**

**Why:** 2026-08-14 书记员（08-11 拉数）交了两条，我复核后：**两条的结论都成立，但两条的
数字都不能直接引用。**

1. **发版日独立访客 8/7/8** —— 数字逐字正确（见 [[release-day-produces-no-exposure]]），但他
   把"三次相同"当成论据强度，而真正的论据是"80% 的日子都 ≤8"。框架错、结论对。
2. **clone/unique 从六月 55–67 掉到今天 1.07** —— **混了两个统计口径**。
   - 六月的 55–67 是**14 天聚合比**（snapshot 对象上的 `count/uniques`）；实际四次六月快照是
     37.85 / 63.81 / 57.11 / 44.12，range 是 **37.9–63.8**，不是 55–67。
   - 今天的 1.07 是 **2026-08-09 单日**的比值（29/27）。今天的**聚合**比是 **5.27**。
   - 同口径真值：聚合 63.8（06-14 峰）→ **5.27**（12 倍降）；单日中位数 52.9（六月）→
     **1.29**（八月剔除发版日）（41 倍降）。**塌方是真的，"55–67 → 1.07"这个写法不是。**
   - 断崖日期对，序列不对：是 **462(06-24) → 68(06-25) → 3(06-26)**，0 首次出现在 **06-29**，
     不是"462 → 3 → 0 两天内"。
3. **他说 08-10 逐日记录缺失 —— 错了，08-10 在库里**（由 08-14 快照的窗口带回）。真正永久缺的
   只有 5 天：`07-05, 07-06, 07-21, 07-22, 07-23`。

**How to apply:** 复核这类二手结论时固定查三样：**(a) 聚合口径还是单日口径**（这两个在本库里
差一个数量级，最容易混）；**(b) 引用的那天在不在库里**（缺失日清单在 README）；**(c) 论据强度
是不是被巧合撑起来的**。结论对但数字错，照样要明说 —— 数字会被下游直接引用。相关：
[[cohort-at-matched-age]]（我自己犯过的同类错）、[[growth-toolchain]]。
