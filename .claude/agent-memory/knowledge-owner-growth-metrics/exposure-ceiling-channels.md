截至 2026-07-05 巡检，PuPu 的增长瓶颈从"安装"转移到了**曝光**：

- **Star 卡死**：33(6/9)→34(6/14发版)→34→34→**33(7/5)**。四周净掉 1 个(unstar)。
- **独立访客持平**：两周窗 52→53(约 26/周)。views 表面下降只是 06-14 发布尖峰(当天92)退出14天窗,非真实下滑。
- **Referrer 通道构成(两期一致)**：github.com(内部/直达)+ Google~10独立(搜索)+ 少量 Bing/Yandex。**0 社交(HN/Reddit/X)、0 社区(Discord/论坛)。** → 只有已经在找 PuPu 或已在 GitHub 上的人能发现它,没有任何放大器。

**判定：自然流量已见顶,项目会长期横盘,除非主动开一条放大渠道。** 这是当前 Growth Score 里唯一真正卡死的维度(Exposure 10/25),也是最高 ROI 的运营杠杆——一次成功的 Show HN / r/LocalLLaMA 帖可把独立访客从 26/周推到数百量级,是唯一能带来量级跳变的动作。

**搜索是可放大的种子**：Google 稳定 ~9-10 独立/期,说明有真实的自然发现——值得配 README SEO / 关键词。

**2026-07-21 更新：细微解冻但天花板结构未破。** star 33(07-05)→**36(+3)**,数周来首次真实净增(此前 33-34 横盘还掉过1);独立访客两窗 53→58(约持平,仍~28/周);**Google 搜索独立访客 10→15(+50%)——搜索发现渠道在稳步长,README SEO 种子有效**。但 referrer 仍 **0 社交 0 社区**,放大器依旧为零。判定不变:自然流量靠搜索缓涨,量级跳变仍需主动开一条放大渠道。**对 0.1.9 的曝光决策(核心结论):** v0.1.8 已实证——好产品发进真空=每次都冷启动(v0.1.8 与 v0.1.7 一样冷,见 [[install-signal-2026-06]])。所以 0.1.9(computer use+商店+新首屏)的「第一印象就绪」门是对的,但就绪必须配一次协同放大发布(Show HN / r/LocalLLaMA),否则再好的首屏也会重演 v0.1.8 冷启。就绪≠发布,readiness 要绑 launch plan。

**2026-08-07 更新:v0.1.9 又发进真空,战略警告应验。** v0.1.9(2026-08-01 发)是「第一印象就绪」门后第一版,但 referrer 仍 **0 社交 0 社区**,star **36→36 完全冻结**(整个 v0.1.9 发布窗零新增 star),独立访客 58→**51(略降)**——即 v0.1.9 和 v0.1.8 一样,发布没绑任何放大动作。**但反例极有力:v0.1.9 在零放大下仍冷启动 2.83 dl/天(一年最佳,见 [[install-signal-2026-06]]),纯靠自然搜索+存量涓流。** 这就是「就绪必须绑 launch plan」的实证第二例——好产品裸发依然冷启,而它裸发都能到 2.83,配一次 Show HN/r/LocalLLaMA 大概率量级跳变。搜索通道继续长:Google 独立访客 15→**18**,新增 **yandex 9 独立**,搜索总计约 28 独立/期(SEO 种子持续有效)。**基础设施变化:Discussions 已开(has_discussions 07-21 false→now true),但 0 帖、无种子、未从 app/README 导流→通道开了没激活(见 [[silent-downloader-gap]])。** 判定不变且更强:放大器仍为零,P0 永远是开一条放大渠道;现在多一条硬证据(v0.1.9 冷启动好=弹药已就位,就差扣扳机)。注意 08-01 clones 尖峰 416/12 独立=发版 CI/镜像噪声,非用户潮,勿读作放大成功。

**Why 这条重要：** CEO 数据优先、最看重"有没有人真在装"。安装信号近期在回升([[install-signal-2026-06]]),但装的人不增长的根因是没人看见 → 运营重心应从"催发布"转向"催曝光"。
**How to apply:** 每次巡检对比 star / 独立访客 / referrer 通道构成三项;只要社交+社区来源仍为 0,P0 永远是"开一条放大渠道"。若某周独立访客突然跳量,先查是不是发了 HN/Reddit(标准脉络见 [[clone-spike-2026-06]] 的甄别方法)。相关:[[silent-downloader-gap]]。
