**规则：呈现层不得在系统从未声明过的情况下显示一个肯定终态。「不显示」严格优于「显示一个推断出的成功」。**

**Why:** 2026-08-08 case `0000-0005-2026-0807`，本领域对此出 `不成立`（进 chief-judge 强制回应清单）。机械理由不是原则，是代价不对称：

**状态指示器的全部功能是调节用户的检查行为** —— 它存在的唯一理由是让用户决定要不要看第二眼。据此：

| 输出 | 用户的下一步 | 出错时的代价 |
|---|---|---|
| 不显示 | 保持默认检查行为 | **零新增** |
| 显示未知 / 降级态 | 可能去看 | 一次多余的查看 |
| **显示推断出的成功** | **主动放弃检查** | **主动抑制了那个本可以发现问题的动作** |

**一个错误的肯定态不是"没能提供信息"，是"提供了一条促使用户停止查找的信息"。** 这是全部状态设计里代价最不对称的一格。

**本仓的实例（别再造第二个）**：`memory_v2_trace_presenter.js:195` 的 `return mode === "active" || "shadow" ? "Complete" : "Unavailable"` 是一次 fail-open 缺省；`trace_chain.js:1941` 把它插进 14px/weight-500 的标题槽，于是**一个缺省值取得了断言的外观**。那条 `Complete` 的完整证据基础只是「这条消息没报错 ∧ rollout 开着」，不含任何一句关于该功能是否成功的陈述。

**繁殖的证据**：`trace_chain.memory_v2.test.js:861-881` 有一条**绿着的**断言 —— journal reload 整体失败的场景下，断言标题仍为 `Memory V2 · Complete`。**fail-open 已经进入本组织自己的正确性定义。** 这是这类缺陷会自我固化的直接证据。

**How to apply:**
- 见到任何"没有坏消息就显示好消息"的分支，按缺陷处理，不按现状接受。
- 出规格时二选一：**不显示该行**，或**显示一个明确标记为未知的态**。取舍属产品，机制属那个缺省所在制品的 owner。
- **注意时点与性质是两件事。** 别人说"本案不修它"（时点）不等于"它不是缺陷"（性质）。这两句要分开呈给裁决者，压成一句会丢掉后者 —— 我在 S-0027 请求 2 就是这么要求的。
- 同一条也适用于把内部枚举缺省美化成产品文案：`resolveMode` 找不到 mode 时返回 `"off"`，经通用 titleCase 变成 span 里的 `Off` —— **对用户断言"这个功能是关着的"（一个用户设置），而事实是它开着并且降级了。把系统故障呈现为用户配置，是最难被纠正的一类错误，因为用户会认为自己已经理解了。**
