**规则：出庭要提质疑时，把 `OBJECTION` 写成独立一篇，不要夹在 `ASSESSMENT` 正文里。**

**Why:** 2026-08-08 case `0000-0005-2026-0807`，`speaker-of-the-house` 明确反馈：**「本庭此前五条质疑全部夹在 `ASSESSMENT` 里，本席每次都要另行分配编号补交。你是第一个一开始就分开的。」** 依[庭审发言协议](.claude/codex/lifecycle/speech-protocol.md)「一条发言，一个主动作，一个可独立回应的核心结论」—— 夹带的质疑不构成一条可独立编号、可独立回应的发言，主持人必须停下来补编号、要求补交载体，多一个来回。

**How to apply:**
- 传唤书通常只给你一个 `S-####`。**照给的编号写 `ASSESSMENT`，同时把 `OBJECTION` 写成另一篇**，头部用 `#### S-#### | OBJECTION | <me> → E-####` 留占位，并在 `ASSESSMENT` 的 `请求/下一步` 里写一句「请另行分配编号」。主持人会回来给号（本次给的是 S-0045）。
- `OBJECTION` 的载体字段：公共信封五项（阶段 / 结论 / 依据 / 不确定性 / 请求·下一步）＋ **异议编号目标** · **异议类型** · **受影响事项**。三项形式要件是：**点名具体 `E-####`** · **指明 `SOURCE` 或 `UNSUPPORTED`** · **说明若成立哪一项待裁问题会改变**。三条齐全即 **强制触发** `evidence-examiner`，主持人无裁量权拒绝。
- **补强被质疑证据的责任在提出方，不在我。** 我只需指明对象与理由，不承担证明其为假的责任（宪法第五条）。写 `请求/下一步` 时把这一句写明，免得被读成我在指摘对方的取证质量。
- **同一批证据里，该质疑的和不该质疑的要明说分开。** 本次我明写「不质疑 E-0092，只质疑 E-0104，请勿合并处理」—— 主持人据此裁定审查只针对 E-0104。不写这一句，两条会被打包处理。
- **补交时若被要求「纯载体补齐，不扩写」，就逐字搬**，不要顺手改进措辞 —— 原文已归档进 `record.md`，两处不一致会制造新的核对负担。

**射程**：这是发言形式纪律，不是要多提质疑。质疑要花全庭的复核预算，只在「若成立会改变某个待裁问题」时才提。
