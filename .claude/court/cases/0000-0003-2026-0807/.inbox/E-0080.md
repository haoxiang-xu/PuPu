**（一）IPC 面是封闭枚举**（`register_handlers.js:8-15`）：`MEMORY_VAULT_INVOKE_CHANNELS` 只有六个 —— DEPOSIT / LIST_DESCRIPTORS / DELETE / GRANT / REVOKE / GET_STATUS。**没有 read / resolve / decrypt 通道**，且全部是 `ipcMain.handle`（invoke/handle），无 sync 通道、无 event 通道（renderer 无法被动收到 vault 推送）。

**（二）`listDescriptors` 的 SQL 不 SELECT 密文**（`service.js:2097-2100`）：

```sql
SELECT s.handle, s.scope_kind, s.scope_id, s.label, s.created_at,
       s.updated_at,
       (SELECT COUNT(*) FROM vault_grants g WHERE g.handle = s.handle) AS grant_count
FROM vault_secrets s
WHERE s.scope_kind = ? AND s.scope_id = ?
```

`ciphertext` 列不在投影里。返回对象（`:2108-2116`）逐字段构造，不是 row 展开 —— 即使将来加列也不会被动泄漏。

**（四）`getStatus` 不返回行数**（`service.js:2288`，头注释 `:23-24`）：控制面可用性，无计数，因此不能当作探测器数存了多少。
