  **一 · blocking 性质认定：`non-blocking` 成立**

  本席依 [`side-cases.md`](../../../codex/lifecycle/side-cases.md) **第 4 步的判据** 裁，不依「两件事有没有关系」裁：

  > - **blocking**: parent case 挂起，待 side case 结案后恢复推进
  > - **non-blocking**: side case 与 parent case 各自独立推进

  **该判据问的是一件事：parent case 是否必须停下来等。** 不是「两案是否相关」，也不是「side case 的结论是否会波及 parent case」。

  **本席认定 parent case 无须挂起，理由三条：**

  1. **parent case 今日具备形成有效产出的能力。** 其待裁三问的对象是 **键名、白名单、制品职责**（`case.md` Q1/Q2/Q3）；UR-1 的对象是 **异常传播路径与失败保证**。三问的任何一问，都不需要先知道「纯观察面写失败应否中止回合」才能作答。

  2. **该依赖的方向是单向且指向未来的。** 已归档的依赖（S-0024 第三节）说的是：parent case 若据「今天结构上不可达」下调严重度，**该下调的有效期以 UR-1 的处置方向为界**。这是一条 **对已作裁定的失效条件**，不是一处 **作裁定前的事实缺口**。前者由裁定的书写形式承载，后者才使程序挂起。**依赖 ≠ 阻塞，正是第 4 步两个定义之间的那条线。**

  3. **反向假设不成立且代价荒谬。** 若判为 blocking，parent case 须挂起，等一个 **尚未立案** 的 side case 走完 议案庭审 → 方案 → 裁定 → 实施 → 验收 的完整 lifecycle；而该 side case 自陈其三个处置方向 (i)/(ii)/(iii) **一个都还没选**（S-0018「问题」节）。**其结果是：parent 的三问被一个与之无因果关系的保证取舍无限期扣押。** 这与 side case 机制「分叉以免相互拖累」的设立目的正好相反。

  **本席须记明自己检验过的最强反对论证，并说明它为何不改变结论：**

  反对论证是：严重度下调若基于「结构上互斥、今天不可达」，而 UR-1 恰可解除那道互斥，则该下调会在 UR-1 被修好的那天 **静默失效且无人知道** —— `speaker-of-the-house` 已指出这恰是 parent case 正在处置的那个失败类（S-0024 第三节）。**本席认为该论证指出的危害真实存在，但它所要求的救济不是挂起。** 该危害的救济是 **把裁定写成附条件且带失效条件的形式**，此项已由 `speaker-of-the-house` 于 S-0024 第三节归档在案。**存在一个比挂起更廉价、且已经就位的救济，即意味着挂起不是必需。**

  **且本席的认定不以该救济被采纳为前提。** 纵使 `chief-judge` 不采纳条件化写法而径作无条件下调，parent case 仍 **有能力** 今日作出裁定 —— 受损的是那份裁定的存续质量，不是 parent case 的推进能力。**第 4 步的判据衡量的是推进能力。** 故本认定在两种分支下均成立。

  **一致性旁证（非本裁定的判据，本席标明其地位以免混用）**：授权清单第 5 项对传票 blocking 性质的判据是「该事实缺口是否阻止当前阶段形成有效产出」。该项管辖传票、不管辖本事项，但其指向与本席结论一致 —— 「纯观察面失败应否中止回合」这一事实缺口，不阻止 parent case 当前所处的 **议案庭审** 形成有效产出。

  **提出方声明「若有角色异议 blocking 性质，其不争、按 blocking 处理」。经查，截至本裁定作出，无任何角色就该关系判断提出异议**；`speaker-of-the-house` 明示不持实体立场。**该条件未触发。** 本席系独立复核后维持，非因无人异议而径予采信。

  **二 · 立案裁定：受理要件满足，准予立案**

  [`side-cases.md`](../../../codex/lifecycle/side-cases.md) **第 1 步** 的受理要件有二：**附证据**，**声明关系**；「无证据支撑的动议不予受理」。

  **要件一 · 证据（满足）。** S-0018 的支撑证据为 **E-0039**，经查已归档于本案 `evidence.md`，`repository | 自证类`，载明跨两仓的 `file:line` 定位、可复跑的取得方式、unchain revision `a4e69f41`，并有 **验证历史**（`S-0005 | 已验证（由 code-owner-runtime 实跑）`）。**要件满足。**

  **要件二 · 关系（满足）。** S-0018 明示声明 `non-blocking` 并附自判理由。

  **本席另查「超出当前 case 范围」这一构成要件。** 该要件源自 [`side-cases.md`](../../../codex/lifecycle/side-cases.md) 首句 —— side case 机制处理的是「**超出当前 case 范围** 的问题」。**若事项本在范围内，分叉本身即为错误处置，应在 parent case 内解决。** 故此项须查。经本席逐条比对 `case.md` 与 S-0018「超出当前范围依据」，**该要件满足**，其中两条本席认为具决定性：

  - **无因果关系。** UR-1 在 sink 触发 **之后** 才发生，且在四个键完全不存在的假设下依然成立。经比对 `case.md` 待裁三问，确无一问以异常传播路径为对象。
  - **正确的传唤名单与 parent case 不同。** UR-1 的链路中段在 `unchain:**`，取舍需 `expert-llm` 与 `expert-architecture`；而 parent case 的必到 5 人（`case.md`）**不含 `code-owner-unchain`**。**一个正确出庭名单不同于 parent 的事项，在机制上就是另一个 case** —— parent case 无法在不重开自身 `FRAMING` 的前提下为它传唤到对的人。

  **关于 E-0039 的自陈限制（静态读取、未做故障注入、未观察过一次真实的 shadow 写失败、未核实发布构建下 shadow 面是否可达），本席明确裁示：不构成立案障碍。** 理由：第 1 步要件是动议须附 **触发该动议的证据**，不是要求证据在实体问题上已然定论。**若于立案关口要求结论性证明，等于要求一个 case 在被开立之前就已被回答，将使 lifecycle 倒置。** 该等限制系依证据规则由提出方主动申明，是证据制度在正常运作，非缺陷。**其对严重度与处置方向的影响，属 side case 自身庭审的实体问题，本席不予预判，一并结转。**

  **`code-owner-unchain` 就「unchain kernel loop 内部是否存在把 durable 异常降级为可继续状态的通路」的在途复核（S-0018 不确定性二），同样不构成立案障碍。** 本席不评价该复核的任一分支孰是 —— 仅认定：**依动议自身的陈述，立案与否不取决于该复核的走向。** 该复核结转至 side case 的 `FRAMING`。

  **三 · 本裁定明确「不裁」的事项（本席据此自限）**

  本席只裁「是否立案」与「blocking 性质」，以下各项 **一律不在本裁定射程内**：

  - **不裁 UR-1 的技术内容。** 尤其 **不选择** S-0018 列举的处置方向 (i) 维持现状 / (ii) 降级为静默并另行可见 / (iii) 降级但标注「观察缺失」 —— 该取舍涉及帧语义与跨层保证，属 side case 自身的实体裁决。
  - **不裁 parent case 的任何一问**（Q1 / Q2 / Q3），**不裁其严重度**，**不裁形状 P**。
  - **不裁 E-0039 的证明力**，只裁其作为受理要件的形式充足性。
  - **不分配议案编号。** 依 `speaker-of-the-house` 角色职责，议案编号以 **原子创建 case 目录** 取得，专属该角色。
  - **不裁 side case 的 track。** S-0018 未自报 track，本席授权清单第 4 项只能对 **自报档位上提一档**，无标的即无裁量；初始定档不在本席授权内，依常规立案流程处理。
  - **不推荐修法。**
