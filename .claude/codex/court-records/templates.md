# 固定模板

[Quorum 索引](../README.md) · [Court Records](README.md)

普通发言直接使用 [**庭审发言协议 · 公共信封**](../lifecycle/speech-protocol.md#公共信封)。以下模板只增加相应类型载荷；公共字段与类型字段的名称及顺序保持不变。

## `Witness` 传票

```markdown
#### S-0012 | SUMMONS | speaker-of-the-house → witness
- **阶段**: 方案庭审
- **结论**: 传唤回答下列单一事实问题
- **依据**: S-0008, E-0003
- **不确定性**: 无法从已查来源确定
- **请求/下一步**: Witness 回答 KNOWN、UNKNOWN 或 UNCERTAIN
- **问题**: ...
- **受影响事项**: ...
- **已查来源**: ...
- **本人知情理由**: ...
- **阻塞状态**: blocking
```

## `Witness` 证言

```markdown
#### S-0013 | TESTIMONY | witness → S-0012
- **阶段**: 方案庭审
- **结论**: UNKNOWN
- **依据**: S-0012
- **不确定性**: 本人不掌握该事实
- **请求/下一步**: 将该问题保留为已知缺口
- **回答状态**: UNKNOWN
- **证据编号**: E-0004
- **答案**: 不知道
- **知识来源**: 本人记忆
- **适用边界**: 仅回答 S-0012 所问范围
- **可佐证线索**: 无
```

## 证据条目

```markdown
### E-0003 | repository
- **来源定位**: `src/example.ts:10-24`
- **取得方式**: 当前 checkout 只读检查
- **提交发言**: S-0008
- **支持/反驳**: 支持 S-0007
- **完整性限制**: 未检查部署环境
- **验证历史**:
  - S-0009 | 已验证 | 内容存在且与引用一致
```

`验证历史` 只能追加。状态至少区分 **已验证**，**未验证** 与 **相矛盾**；`Witness` 证言对应使用 **已佐证**，**未佐证** 与 **相矛盾**。
`Witness` 证言的证据条目使用来源类型 `human-testimony`，并以 **提交发言** 指回对应 `TESTIMONY`，不在 `evidence.md` 复制证言答案。

## 闭庭摘要

```markdown
#### S-0014 | SUMMARY | speaker-of-the-house → case
- **阶段**: 方案庭审
- **结论**: 闭庭条件已经满足，提交以下忠实汇总
- **依据**: S-0001, S-0004, S-0006, S-0007, S-0010, S-0012, S-0013, E-0005
- **不确定性**: S-0012
- **请求/下一步**: 提交 Chief Judge 进行方案裁定
- **共识**: S-0004, S-0006
- **分歧**: S-0007 ↔ S-0010
- **已知缺口**: S-0012, S-0013
- **候选方案**: 0000-0003-2026-0806
- **风险**: E-0005, S-0010
- **强制回应事项**: S-0007
- **未答 non-blocking 传票**: 无
```

## 方案文档

```markdown
---
case_id: 0000-0001-2026-0806
updated_at: 2026-08-06T19:00:00-07:00
---

# 方案

## 0000-0003-2026-0806
- **提出发言**: S-0011
- **目标结果**: ...
- **实施范围**: ...
- **关键步骤**: ...
- **风险**: ...
- **可逆性**: ...
- **回滚/补救方式**: ...
- **验收标准**:
  - AC-001 | ...

### AM-001
- **提出发言**: S-0015
- **影响字段**: ...
- **原值引用**: ...
- **修正内容**: ...
- **修正理由**: ...
```

方案正文与修正块只追加，不在原位置改写。裁定采纳修正时，同时引用方案编号与 `AM-###`；修正只允许影响实施范围，步骤，风险，可逆性或补救方式。若改变方案的目标结果或任何验收标准，则不得使用修正块，必须取得新的方案编号并提交包含完整验收标准的新方案。

## 裁定文档

```markdown
---
case_id: 0000-0001-2026-0806
updated_at: 2026-08-06T20:00:00-07:00
---

# 裁定与授权

## R-0001 | 方案裁定 | 2026-08-06T20:00:00-07:00
- **裁定身份**: Chief Judge
- **记录类型**: PLAN_RULING
- **依据**: S-0001, E-0003, 0000-0003-2026-0806
- **裁定**: ...
- **强制回应**:
  - S-0007: ...
- **获准 action**: ...
- **验收标准引用**: 0000-0003-2026-0806#AC-001
```

`记录类型` 只允许 `MOTION_RULING`，`PLAN_RULING`，`EXPRESS_RULING`，`RECONSIDERATION_RULING`，`PROCEDURAL_RULING`，`FAST_TRACK_DIRECTIVE`。`EXPRESS_RULING` 在公共裁定字段后按顺序追加 **议案结果** (`APPROVED / REJECTED`) 与 **获准方案** (完整方案编号或 `NOT_APPLICABLE`)，以一个记录同时完成两项取舍。组合约束如下:

- `APPROVED` 必须同时给出完整 **获准方案**，至少一项 **验收标准引用** 与非空 **获准 action**，随后进入 `implementing`
- `REJECTED` 的 **获准方案** 必须为 `NOT_APPLICABLE`，**验收标准引用** 与 **获准 action** 必须为 `无`，随后进入 `closed`

`FAST_TRACK_DIRECTIVE` 没有方案正文可引用，因此以该记录作为标准正文，并将 **验收标准引用** 字段替换为一个或多个带 `AC-###` 的 **验收标准** 块；例如 `acceptance.md` 可引用 `0000-0001-2026-0806#R-0001#AC-001`。每次新裁定或推翻都在文件末尾追加完整块，不修改旧块。

## 验收文档

```markdown
---
case_id: 0000-0001-2026-0806
updated_at: 2026-08-06T21:00:00-07:00
---

# 验收

## 2026-08-06T21:00:00-07:00
- **验收身份**: Acceptance Inspector
- **验收标准引用**:
  - 0000-0003-2026-0806#AC-001
- **检查方法**:
  - 0000-0003-2026-0806#AC-001 | ...
- **观察结果**:
  - 0000-0003-2026-0806#AC-001 | ...
- **证据**: E-0008
- **验收结论**: 通过
```

`acceptance.md` 不复述验收标准正文。标准发生变化时，必须先产生新的方案或 Fast Track 指派及相应裁定，再以新的编号引用进行验收；不得直接在验收文档中改写标准。
