# Track 分档

[Quorum 索引](../README.md) · [Case Lifecycle](README.md)

并非所有 case 都需要走完整的九步流程。case 依据 **客观属性** 分为三档，**不依据事情的大小或重要性** —— 大小是主观判断，判断本身即成本。

| Track | 准入条件 | 流程 |
|---|---|---|
| **Fast Track** | 以下四条 **全部** 满足 | 免庭直行 |
| **Express** | 可逆 且 不改变契约，但 跨 owner 或 存在争议 | 单次庭审 + 单次裁定 |
| **Full** | 触发以下任一条 | 完整九步 |

**Fast Track 准入四条 (缺一不可)**:

1. **完全可逆**: 一次回滚即可复原，无数据迁移，无外部副作用
2. **不跨 owner**: 全部落在单一 owner 的所有权边界内
3. **不改变契约**: 不触及 接口，数据结构，事件语义，或任何对外可见行为
4. **不涉及** 金钱支出，对外发布，或对外公开

**Full 强制触发条件 (任一即触发)**:

1. **不可逆**: 数据迁移，删除，发布，对外公开，金钱支出
2. **改变契约**
3. **有 `Expert` 出具 不成立 鉴定意见**
4. **跨三个及以上 owner**

各档流程:

- **Fast Track**: `Chief Judge` 直接指派 owner 执行，**无议案庭审，无方案庭审，无另行裁定阶段**
    - 但 **保留验收**: `Acceptance Inspector` 照常执行 **验收评估** (第 7 步)，验收不通过照常进入 **验收庭审**
    - 但 **保留归档**: 事后由 `Speaker of the House` 补录一条 fast track 归档记录，编号照常分配
    - 快车道砍掉的是 **前置庭审**，不是 **验收** 与 **留痕**；庭审的成本在于多 agent 多轮，验收与归档各只有一次
- **Express**: **议案庭审** 与 **方案庭审** 合并为一次庭审，同时收集 **意见和建议** 与 **方案设计**；`case.md` 使用 `phase: combined`，`Chief Judge` 以一条 `EXPRESS_RULING` 同时记录议案结果与获准方案，只做 **一次裁定**。裁定通过后进入 `implementing`，驳回后进入 `closed`；其余阶段与 Full 相同
- **Full**: 完整九步，无省略

**档位判定**:

1. **提出者自报**: 提出议案时声明 track，与 side case 动议自报 blocking / non-blocking 采用同一机制
2. **`Procedural Judge` 升档权**: 认为自报档位过低的，裁定 **上提一档**；升档裁定不可下调，只能上提
3. **`Expert` 异议**: 任何 `Expert` 对档位提出异议的，该 case **自动升至 Full**，无需裁定
4. **`Dimension Owner` 无档位异议权**: `Dimension Owner` 恒定到场，且 **分歧是其常态产出**；若 **反对** 即升 Full，分档机制形同虚设。其反对意见由 **强制回应效力** 保证不被漏看，但不改变档位

**升档时的产出继承**: case 升档时，升档前已完成的 **庭审产出** (意见和建议，方案，发言记录，证据记录) **不作废**，作为升档后流程的输入直接沿用；升档只补足 **尚未经过的阶段**，不重走已经走完的阶段。`Speaker of the House` 归档时标注该 case 的 **档位变更记录** 及变更时点。

**Fast Track 的方案依据**: Fast Track 中，`Chief Judge` 的 **指派说明** 即为[宪法第二条](../constitution.md)所要求的方案依据 —— 它同时是方案与裁定，因而必须写明 **可验收的完成标准**。缺少完成标准的指派，`Acceptance Inspector` 拒绝受理验收 (见 [`Acceptance Inspector` 角色职责](../roles/acceptance-inspector.md#角色职责))。
