## Settled recovery design (pre-implementation)
- Keep the rejected send terminal in the existing durable wire lease. Normalize only confirmed HTTP input-context rejections to context_length_exceeded with the new confirmed input_context_rejected flag (diagnostic v3, lease v5). Old diagnostics carrying the same code do not authorize recovery. No automatic replay after stream ambiguity or a successful generation stop.
- Introduce kernel phase on_context_limit after failed-send accounting and before any model-result/tool application. The owning ContextCompilerHarness alone can persist a recovery and acknowledge it through a HarnessDelta. Without an active durable context owner, leave the rejection explicit; legacy/off paths must not silently discard history. Recovery must not pretend an unsupported path has compacted.
- Journal event type context.provider_recovery; CLOSED payload schema unchain.context_provider_recovery.v1. Required fields: schema, iteration, provider, model, ordinal, available_input_tokens, source_input_event_id, source_input_store_seq, rejected_build_id, before_message_bytes, estimated_input_tokens, parent_recovery_event_id. Producer is the trusted owning ContextRuntime after a confirmed rejected input; consumer is the same runtime's compile/fetch path. Bind to the exact AttemptRef and current canonical input receipt, never arbitrary message text. IDs and operation hashes are deterministic from attempt/iteration/ordinal and canonical payload. Reject gaps, conflicting parents, cross-provider/model/input fences or malformed fields.
- Latest ordinal is at most 2 per logical model call. Set the new available input budget no higher than 75% of both its previous budget and previous measured input estimate. Preserve the real model window and output reserve; increase the transport/uncertainty margin to lower the input allowance while retaining the budget arithmetic invariant. Recompile through the existing coordinator, checkpoint store and canonical journal; do not mutate transcript or clear current required input/tool pairs. Verify message bytes AND estimated input are strictly smaller than the rejected projection before any new send; otherwise fail with an explicit irreducible-context error.
- Each recovery's provider wire uses the existing occurrence_sha256 namespace derived from the verified recovery event identity. This creates a new immutable provider request subject while preserving execution, owner attempt and logical iteration. It never reuses the failed wire bytes. Existing exact result/lease accounting remains authoritative. No tool result has been applied for a rejected request, so only model fetch/context preparation is retried; completed business tools are not rerun.
- Cold restart reads the committed recovery event and applies the same budget before provider preparation, selects the same occurrence namespace, and recovers completed results. A crash after rejection but before recording replays the recorded failure without a second send, then records the deterministic recovery. A crash after record/compile/send/result follows the existing durable request/result uncertainty contract, never inventing success or resending an uncertain attempt.
- Record a public additive provider_context_limit_recovery_v1 runtime manifest feature. PuPu tests must distinguish updated supported runtime from an older imported runtime; do not admit based on Git SHA or checkout paths.

## Implementation decisions and newly discovered boundaries

BC-005: classifier -> ProviderFailureDiagnostic -> durable ProviderRequestLease -> Kernel recovery. VERSIONED closed v3 diagnostic has exactly schema/http_status/provider_code/parameter/input_context_rejected (the last value must be true, HTTP400/422, normalized code, empty parameter). Lease v5 carries that diagnostic. v1/v2 diagnostics and v2/v3/v4 leases retain exact canonical bytes and hashes; absence of the new flag is never proof of recoverable input rejection. Unknown fields/hybrid versions fail closed. AC-002/AC-005/AC-006 include migration, SQLite reopen, conflicting code/message and no-resend tests.

- The canonical journal's secret guard already permits the numeric metric `estimated_input_tokens`; use this canonical name instead of weakening sanitization for a newly token-shaped field.
- A canonical input can authorize only one build. Explicit recovery events authorize distinct deterministic derived builds; the original claim, failed wire, request lease and transcript remain immutable. The strict coordinator independently verifies scope, source cursor, parent/ordinal and rejected-build chain.
- Recovery projection is pinned to the recovery authorization event's exact contiguous journal prefix, after live-journal input/terminal admission. Later wire/result receipts cannot alter that build's operation payload. A meaningful RED cold-result-CAS test reproduced an operation-payload conflict before this fence; GREEN reuses the committed result without another send. Ordinary builds retain their existing live snapshot behavior.
- Ollama previously converted HTTP rejection evidence to text. Preserve only a classifier-confirmed real HTTP rejection through its transport; HTTP200/stream errors retain uncertainty behavior. No local-model inference is performed.
- The new public feature is required consistently by Python admission, Electron admission, release artifact verification and the shared Windows protocol fixture. Missing feature -> explicit incompatible-runtime verdict. The `.js` Electron test entrypoints require their `.cjs` suites; those remain aligned.
