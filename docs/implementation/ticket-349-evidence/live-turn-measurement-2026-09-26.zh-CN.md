# #349 真实短对话测量（首次样本）

本次在隔离 Electron 实例中运行当前冻结候选、固定 Unchain wheel 和真实
`openai:gpt-4.1`。同一新会话连续发送要求返回 `READY-n` 的短消息；没有工具调用。
日常桌面未参与。

## 全轮应用耗时

七次成功请求的 Test API `latency_ms`（从发送到最终回复）为：

`3806, 2824, 3073, 3767, 5517, 4736, 4046` ms。

| 指标 | 值 |
| --- | ---: |
| 样本数 | 7 |
| 最小值 | 2824 ms |
| 中位数 | 3806 ms |
| 均值 | 3967 ms |
| p95（nearest-rank） | 5517 ms |
| 最大值 | 5517 ms |

同一会话去掉第一条后的六次中位数是 3906.5 ms。测试中一次紧接前一轮完成后的
请求返回“正在恢复被中断的运行”，随后下一条正常完成；该失败不计入统计，也不是
本次延迟结论的样本。

这些是**整轮完成时间**，包含真实模型等待、桌面桥接、前后处理和最终落库；它们
不能作为首字时间、模型请求前本地准备时间，或 Memory V3 优化前后差值。当前测试
接口只在完成后返回，因此还需要从流式事件或侧车时序记录取得首字样本。

## 对照的本地准备数据

同一固定候选的既有 100 次/单元本地基准只测“请求工厂 + context compile”，不含
模型、网络、流式和桌面。100 条历史时：

| 场景 | cache off 中位数 | cache on 中位数 | 差值 |
| --- | ---: | ---: | ---: |
| unchanged history | 298.632 ms | 181.909 ms | 快 116.723 ms（39.1%） |
| committed tool continuation | 299.176 ms | 250.762 ms | 快 48.414 ms（16.2%） |

所以现有证据说明：缓存减少了长历史的本地准备时间，但真实短回复的约 2.8–5.5 秒
主要仍被整轮模型路径主导。下一轮应采集同一请求的 `request_ready`、首个
`token_delta` 和最终完成时间，才能定位剩余的用户可感知等待。
