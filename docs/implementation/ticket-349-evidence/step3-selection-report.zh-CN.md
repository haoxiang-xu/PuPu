# #349：后台任务误用旧模型的并发修复

状态：修复完成，开发验证通过，等待用户要求的下一次验收。本记录不代表正式验收通过，也未更新日常桌面端。

## 修复行为

原先后台先读取模型配置，再领取任务。两步之间如果新一轮更换模型，后台可能拿旧配置处理新任务。

现在先由官方运行库领取任务，再读取当前配置。读取配置、检查待恢复记录和取得对应临时参数使用同一把注册锁；发现注册尚未恢复时，不创建模型调用，任务进入可重试状态。恢复后，同一个任务使用新配置完成一次。

取得配置后立即释放锁。模型构建和网络等待期间，新一轮仍能注册自己的配置；已经开始的调用保持自己的配置快照，后续调用读取最新配置。没有新增每个任务的历史配置存储，也没有修改 Unchain wheel。

只有注册异常时，后台任务的下次重试时间会设为一秒后。这是失败恢复安排，不是正常模型请求固定等待一秒，也不阻塞前台回答。

本次产品修改限于 `unchain_runtime/server/memory_v2_background_worker.py`；新增六项并发测试，计划中记录 BC-349-10、SEQ-349-07、AC-349-21。

## 验证结果

- 冻结候选与固定 wheel：107 项测试通过，耗时 28.39 秒，覆盖并发选择、延后准备、后台恢复、legacy 路径、graph root completion。
- 将新增六项测试运行在上一版冻结候选上：5 项失败、1 项通过；五项失败均涉及旧配置误用，修复后全部通过。
- 重跑上一轮验收的原始交错复现：模型调用为零，任务保持 pending，结果为 retry；另有真实双线程测试验证冷恢复后同一任务只完成一次。
- 独立桌面实例启动了新的 Python sidecar，并使用固定 wheel 完成真实模型验证：候选保存成功，后台任务 completed、attempt_count=1，候选 applied；桌面读取接口返回完整的 53 字节合成记忆内容。
- 两轮真实前台请求的应用记录总耗时分别为 3827 ms、6812 ms。这是功能验证中的整轮耗时，不是首字时间或优化前后对照，不能据此宣称延迟改善。
- 测试后重新核对 375 个冻结文件及对应工作区文件，内容未变。测试会话、独立桌面实例、临时配置目录、依赖软链接和功能开关已清理；日常桌面进程仍在运行。
