# 独立工作后移：本轮实施与实测

本轮完成了两项后移，但**没有测出整段准备时间的改善**。这两项原本只占
毫秒级耗时，无法解释此前观察到的约 6 秒等待。不要把本报告视为已解决首字延迟。

## 行为变化

- 主模型启动前不再创建记忆整理执行器；只有实际调用它时才创建。
- 后台整理配置登记移到回答完成、终态记录验证通过之后。普通对话和 graph
  都先保存配置，再保存整理任务；登记失败不会产生半配置任务，重试不会重复入队。
- 上下文、技能与工具定义、权限、输入及工具结果保存保持原有顺序。已发送的
  上下文和已完成的 RunBundle 不因后台工作变化。
- 没有增加等待、定时器、线程或模型调用。详情面板原本已按展开读取，因此没有
  再添加一套延迟读取机制。

## 耗时

两个冻结版本使用同一个 Unchain wheel，每种情况 30 个有效样本，另有一次预热。
使用真实 SQLite 和真实主机准备流程；**没有真实模型请求，也没有人为等待**。
两个版本分进程测量，整段耗时受文件系统和调度影响，不能把微小差异当作净收益。

## 验证

- 新增测试在修改前 10 项失败，直接复现提前构造、提前登记；修正一个测试
  snapshot 调用方式并更新旧测试的 eager 构造预期后，本轮新增 13 项通过。
- 冻结候选 + 同一个已安装 wheel：**223 项测试、6 项子测试通过**。
  覆盖普通 root hook 的真实 producer → 官方 module consumer、graph 入队顺序、
  并发首次构造、错误工厂、失败重试、二次消息、交互/graph 恢复、删除和后台重启。
  [完整结果](step3-defer-tests.txt)。
- 初次冻结脚本缺少生成的 toolkit resource，测试收集失败；补齐同一 r7 已冻结
  resource 后重新冻结并执行以上测试。失败运行不计入通过证据。
- 隔离 Electron 实例和 Python sidecar 完整重启后均报告 Memory V2 ready。
  [启动](step3-defer-desktop-ready.json)、[重启](step3-defer-desktop-restart-ready.json)。
- 同一新聊天连续两次真实 GPT-4.1 请求均正常结束，回答各为 `OK`。应用报告整轮
  耗时 **3505 / 3008 ms**。这是功能冒烟，**不是首字时间，也不是受控前后提速对比**。
  未产生真实模型整理候选；后台整理恢复由上述 SQLite/官方 worker 测试验证。
  [原始记录](step3-defer-live-after.json)。
- 测试聊天已删除；诊断应用已停止；复制的隔离凭据配置、临时依赖链接和功能标记
  已清理。用户日常应用未更新或重启。
