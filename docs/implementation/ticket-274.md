### Decision and execution order

1. Add an internal provisional callback capability to `ContextRuntime.compose_event_callback`: it may send an Ollama reasoning preview to the host without writing the durable event journal, then persist that same raw reasoning event without re-sending it after the durable provider result commits. A discard signal removes the preview when the physical send fails, is retried, cancelled or abandoned. Keep the ordinary callback's persist-before-host behavior unchanged. Validate the provisional event's provider, exact raw shape, attempt binding and nonempty delta.
2. Only `OllamaExactRouteTransport` uses that capability. Buffer the unchanged strict provider events for committed replay. Assign each previewed chunk a distinct ephemeral ID derived from the physical send ID and its buffered index. On successful result release, persist previewed events once and broadcast the other buffered events normally; on discard, reset every still uncommitted preview and clear the buffer. If a later journal append fails, keep already committed chunks visible and reset only chunks not committed. A plain callback without the capability retains existing delayed delivery. Do not alter the other exact transports, provider wire body, result CAS or request lease behavior.
