## Context Status prefix optimization — 2026-09-11

The owner expanded this follow-up to all model providers. Move runtime-generated context telemetry out of the stable instruction prefix. Preserve caller-authored messages, including text beginning with `[Context Status]`; do not migrate historical messages by text matching. No explicit remote cache or feature flag is introduced.

- BC-006: Unchain ContextUsageOptimizer -> optimizer state -> build_model_turn_request -> native/exact provider transport. The optimizer writes statistics plus a CLOSED `request_note` record with exactly `schema_version=1`, `context_version_id`, `iteration`, `current_tokens`, and `max_tokens`. Counts/iteration are nonnegative exact integers (max_tokens positive). Malformed or unknown records fail before provider dispatch; a different context version/iteration omits stale telemetry. Disabled optimization clears the record. Missing records (including old checkpoints) mean no new suffix. Current records project to a plain `{role: user, content: string}` runtime-information suffix after replay assembly, in both primary and available fallback inputs; provider converters retain their existing strict schemas. This is informational telemetry, not a replacement for any system instruction. It never enters semantic conversation history or latest-user-query selection. Existing frozen requests/replay artifacts are not rewritten. No public wire or protocol-manifest schema changes; deployment identity remains BC-005.
- AC-007: real optimizer -> kernel state -> request builder -> strict provider wire for OpenAI, Anthropic/Hyperspace, Ollama, Gemini. Verify exact note keys, stable instruction/history prefix as counts change, tool pairs and native signatures unchanged, no note accumulation/self-counting, no caller-authored status deletion, disabled/empty/stale behavior, malformed/unknown/version rejection, and frozen wire JSON roundtrip. Ordinary provider inputs without the optimizer retain their bytes.
- SEQ-004 (BC-006/005, AC-007/006): bind note to context version and iteration; first message -> repeated preparation -> assistant/tool results -> next iteration -> second user message. On checkpoint reopen, refresh through before_model before building a new request; old checkpoints without a record add nothing. Existing historical status text is preserved. Normal/graph/subagent share the host's optimizer factory; host contract coverage must use the newly built wheel.
