### F-A4 cold observation/recovery decision (before implementation)

A cold pending lookup will inspect an active launch only when its graph is `running`. It must find an existing active session guard, and prove that guard's transport is this launch's root or a persisted resume binding to that root. It asks the existing process-identity-aware session registry to acquire that exact guard; **only `reclaimed`** (proved stopped owner) authorizes runner recovery. Live/owned/unknown ownership, missing guards and mismatched source bindings confer no authority. Hold the interaction lock, recheck launch/graph, call installed `DurableWorkflowRunner.recover()` without dispatch handlers (conservative `outcome_unknown`, never resume/repeat), fail the matching transport, and release only the reclaimed guard. Parent/child recoverable completion is deliberately not auto-advanced by a read.

Also use this same graph settlement at the already-proved transport takeover seam, before its existing typed fail-closed refusal. Unknown outcome is terminal for launch history (including reads after a new root); a later cancel/retry must retain `outcome_unknown`, never relabel it as an unexecuted cancellation. A true subprocess test will approve a real Core write, SIGKILL after the real handler returned but before node sealing, then use a cold host/control reader and verify exactly one effect. Positive controls cover a live owner, a missing guard, wrong binding, unrelated new root, normal completion and subsequent new send.

Recovery fault rule (before implementation): keep a process-local set of exact **replacement guard snapshot digests** obtained from a successful `reclaimed` acquisition. If a graph/transport write fails, retain that guard and proof for retry by this process. A retry may use a reentrant guard only when the entire current snapshot matches that proved digest; mere reentrancy is never authority. If this process itself dies, the durable session registry can prove its death and reclaim again. Remove the proof/release the guard only after the graph is terminal and transport settlement succeeded. A terminal unknown graph with a leftover dead-owner guard can finish that same cleanup without changing the graph. No new durable domain payload or caller-controlled capability is introduced.
