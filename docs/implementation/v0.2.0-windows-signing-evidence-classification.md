## BC-001 — native observations to signing evidence

reported paths for every payload EXE/DLL and the exact installer. PowerShell
collects observations; one production Node projector owns classification/counts.
Transport: a temporary JSON file, then the existing canonical evidence file.

Admission is CLOSED. Observation schema `pupu.windows-signing-observation.v1`
has exactly `schema`, `evidence_schema`, `run_id`, `source_revision`,
`package_version`, `target_id` and `files`. Each file has exactly `path`,
`payload_path`, `sha256`, `authenticode_status`, `signer_subject` and
`signer_thumbprint`. Only the installer has a null payload path. Payload paths
are unique Windows relative paths; reported paths must bind the same payload
root and cannot escape or alias another record. Run/source/schema/target are
validated, not inferred from arbitrary input fields.

normal `signed_files`, including already signed Tcl/Tk files. Only the two exact
controlled Tcl/Tk paths may become unsigned exceptions. Preserve the historical
`UnknownError` fixture policy alongside `NotSigned`; reject `HashMismatch`,
`NotTrusted`, unknown status values and non-Valid ordinary payloads. This narrows
the previous consumer's arbitrary non-Valid string allowance deliberately.
Use an observational exclusion reason; accept the exact historical reason when
reading older evidence without claiming a current SignTool rejection.

Wire schemas remain `pupu.windows-release-candidate-signing.v1` and
`pupu.windows-signing-qualification.v1`, with their existing exact key sets.
The canonicalizer remains unchanged and sorts without inventing observations.
Zero/one/two exception arrays must remain arrays across the PowerShell boundary.
Projection failure stops before publishing evidence. Do not rewrite old run
artifacts or change old unsigned records into signed records without certificates.

## BC-002 — package gate and sealed Candidate admission

The Candidate package gate and assembler/verifier use the same strict signing
validator. The package CLI computes the expected installer SHA-256 from the
actual installer bytes, separately from the supplied evidence, and binds the
explicit run ID, commit, version and canonical installer name. Evidence must not
provide its own expected hash or identity.

The unsigned set is a subset of the two-path allowlist, not a required pair.
Each controlled Tcl/Tk path must be covered exactly once by either the normal
signed payload prefix or the unsigned subset. Reject omissions hidden by count
changes, overlap, duplicate/aliased paths, unknown exception files, wrong payload
prefixes, unknown fields/schema, invalid identity and installer hash mismatch.
Valid-in-unsigned remains forbidden. Normal signed entries retain certificate
subject/thumbprint, hashes and the required signed elevation helper/launcher.

Counts: payload = signed payload + unsigned exceptions; signed evidence = signed
payload + one installer. Tests assert these independently of the production
projector. Existing signing-qualification consumers retain their original
wire/schema and receive the same observed-state classification.
