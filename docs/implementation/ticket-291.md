## Settled decisions

- **P-D1 Admission**: add `_RuntimeProtocolRequirement(id="skills", major=1, minimum_minor=0, features=frozenset({...six features...}))` to `_REQUIRED_PROTOCOLS`; sidecar build fails closed (existing `unchain_runtime_protocol_required_protocol_missing`) on an older wheel. No import-existence shortcut.
- **P-D2 Inventory (backend authority)**: new module `unchain_runtime/server/skills_inventory.py`: `build_skill_descriptors(*, installed_packs, selected_toolkits) -> list[SkillDescriptor]` (every installed pure-skill pack → skills-only descriptors with `source="skillpack"`, `source_id=<pack toolkit id>`, `base_dir=None`, policy flags + metadata + aliases from the stored row; toolkit-embedded skills only from *selected* executable toolkits, via `Toolkit.skills` set by Unchain for builtins and by `build_mcp_runtime_toolkit` for MCP rows) and `build_skills_config(*, workspace_root, settings) -> SkillsConfig` (`project_root=workspace_root`, `include_project_dirs=workspace_root is not None`, `include_user_dirs=settings.skills.include_user_dirs` (default True), `reserved_commands=("btw","fyi","queue","steer")`, `extra_dirs=()`). `resolve_skill_inventory(...) -> SkillInventory` builds a registry over `Toolkit(skills=descriptors)` and returns `list()`. Never connects an unselected MCP server (descriptors come from the persisted store rows, not from a live connection).
- **P-D3 Mounting**: `_build_developer_agent` appends `SkillsModule(config)` right after `ToolsModule` and passes the pack descriptors by adding a skills-only `Toolkit(skills=pack_descriptors)` to the `ToolsModule` tools tuple (so the registry sees them through `builder.toolkit.skills`). Guard: skipped when `options["_recipe_subagent_run"]` is truthy (unchanged-path test required). Graph/recipe step agents (:10376) are untouched.
- **P-D4 Inventory route (BC-005)**: `GET /skills/inventory` (auth like `route_skillpacks.py`), query `workspace_root` (optional), response CLOSED schema `pupu.skill_inventory.v1`: `{"schema", "revision", "skills": [{"id": <identity key>, "name", "description", "source", "source_id", "aliases": [...], "model_invocable", "user_invocable", "reserved": bool}], "diagnostics": [{"kind","name","source","source_id","message"}]}`; sorted by name; no bodies. Renderer `plugin_skill_sync.js` registers `/name` commands from this response (`expandsTo: ""`, `sourceToolkitId` = source_id when source is `skillpack`/`toolkit`, `availability` = `user_invocable && !reserved`), refreshed on toolkit-catalog refresh, workspace switch and settings change. The renderer sends `options.skill_inventory_revision` with every composer send; `route_chat` compares it with a fresh `resolve_skill_inventory(...)` revision for the same workspace/settings and returns `409 {"error": {"code": "skill_inventory_stale"}}` before opening the stream when they differ; the renderer refreshes the inventory and re-sends. An absent field skips the check (programmatic sends).
- **P-D5 Renderer send path**: `buildComposerSend` keeps `findCommandTokens` for `commands`/`extraToolkits` (per-run pack selection unchanged) but sets `outgoingText = rawText` (no trim, no stripping, no prefix); empty-input validation keeps using its existing trimmed check. Composer sidecar v1 written with `templateLength: 0`. `buildContextCompositionHintV2` therefore mints nothing. Edit path (:13598) and retry go through the same builder.
- **P-D6 Migration**: canonical name = `lower(name)` with `_` → `-`, other invalid characters → `-`, collapsed and trimmed hyphens, truncated to 64; when it differs from the stored name the stored spelling becomes an alias. `normalize_skill_rows` emits rows `{name (canonical), aliases, description, body, tools, model_invocable, user_invocable, metadata, title, phase, degraded: [...]}`; collisions inside one pack keep the first row and record `degraded: ["name_collision:<other>"]`. `skill_pack_import.js` parses `disable-model-invocation` / `user-invocable` / unknown keys into `modelInvocable` / `userInvocable` / `metadata` on import. Idempotent (applying twice yields the same rows); historical chat messages untouched.
- **P-D7 Settings**: `skills.include_user_dirs` boolean in the runtime settings namespace (`readNamespace("runtime")` pattern, `api.unchain.js:74`), default `true`, forwarded as `options.skills = {"include_user_dirs": bool}` on each send and read by `build_skills_config`.
- **P-D4a IPC (BC-007, added at formal-ticket time)**: the renderer cannot call the sidecar directly; the inventory rides one new Electron IPC channel `CHANNELS.UNCHAIN.GET_SKILL_INVENTORY = "unchain:get-skill-inventory"` (preload bridge `unchainAPI.getSkillInventory({ workspaceRoot, includeUserDirs })` → main `unchainService.getMisoSkillInventoryPayload(...)` → `GET /skills/inventory?workspace_root=&include_user_dirs=`). Request shape CLOSED `{ workspaceRoot: string, includeUserDirs: boolean }` (main validates types, drops anything else); response = the sidecar's `pupu.skill_inventory.v1` object passed through unchanged. The toolkit-embedded skills of *selected executable toolkits* keep flowing through the existing catalog-v2 → `plugin_skill_sync` path (commands with `sourceToolkitId`, now without `expandsTo`); the inventory covers packs + workspace/user skill directories and its `revision` is what the stale check compares.
- **P-D8 Presentation**: chat bubble renders `content` verbatim with command chips from the sidecar (already the case); the Context Composition panel shows the two Unchain categories; no new UI component → no design-option round with the user.

## Integration corrections (2026-09-21, CP1/CP2)

- **P-D3 mounting shape changed.** Injecting a synthetic skills-only `Toolkit` into `ToolsModule` broke existing adapter tests that enumerate the mounted toolkit ids and the module order (`VaultSinkAgentModule` at index 1). Unchain gained `SkillsConfig.extra_skills` (programmatic descriptors, rank 600) so PuPu passes pack descriptors through the config; `SkillsModule` is appended right after `PoliciesModule`. Selected executable toolkits' embedded skills still arrive via `builder.toolkit.skills` (builtins from Unchain's manifest loader, MCP via `mcp_toolkits._attach_record_skills`).
- **Lazy-export mocks.** Several adapter tests mock `importlib.import_module`; `unchain.tools`' lazy `__getattr__` uses it, so PuPu code imports `SkillDescriptor` from `unchain.tools.models` (submodule import) instead of the package.
- **Pinned-wheel tests.** Five backend tests hard-coded the sibling `../unchain/src`; they now honour an explicit `UNCHAIN_SOURCE_PATH` (and `_ensure_unchain_on_path` no longer injects the sibling when the explicit path is already importable). Backend suite command: `cd unchain_runtime/server && UNCHAIN_SOURCE_PATH=$PWD/../../.venv/lib/python3.12/site-packages ../../.venv/bin/python -m pytest tests/ -q`.
- **409 handling (P-D4).** `use_chat_stream.handleSkillInventoryStaleError` resyncs the inventory and shows the `chat.skill_inventory_stale` toast (en/zh-CN); the send is not auto-retried — the user resends with the refreshed revision.
- **Inventory refresh triggers.** Mount, toolkit-catalog refresh and the ready transition; workspace-switch / settings-change listeners were not added (no existing subscription mechanism) — the 409 check is the safety net. Follow-up candidate.

## Audit corrections (feature audit 2026-09-21, Overall FAIL → fixes)

- **P1 — one effective inventory.** `GET /skills/inventory` takes `toolkits=<selected ids>`; `skills_inventory.embedded_skill_descriptors` turns the selected executable toolkits' catalog `[[skills]]` rows into descriptors with `source="toolkit"`, `source_id=<catalog id>`; `_build_selected_toolkits` attaches the very same descriptors to every instantiated toolkit (`attach_embedded_skills`), and the 409 check resolves with `options.toolkits`. The renderer registers skill commands from the inventory only (the toolkit-catalog path no longer registers skills); embedded skills of *unselected* toolkits are therefore not offered (their tools would not be available either). The inventory revision (Unchain U3) now binds the effective alias→identity map and reserved commands, so an alias retarget or shadow change is a stale 409, not a silent switch.
- **P2 — collisions keep every row.** `normalize_skill_rows` resolves canonical collisions deterministically: the exact canonical spelling owns the name, other members get `<canonical>-N` with their raw spelling as alias; both sides carry `name_collision:` notes; idempotent.
- **P3 — policy flags.** Every present spelling (`model_invocable`, `modelInvocable`, `disable-model-invocation`, `disable_model_invocation`, `disableModelInvocation`, `user_invocable`, `userInvocable`, `user-invocable`) is evaluated; a present-invalid value is a diagnostic and restrictive; valid spellings combine restrictively. Joint re-verification follow-up: an explicit `null` (JSON `null` on a stored/API row, e.g. `model_invocable: null`) is *present-invalid*, not absent — `_resolve_policy_flag` no longer skips `None` values, so it becomes `invalid_flag:<canonical>` + restrictive and reaches the run as `model_invocable=False`/`user_invocable=False` (regression in `test_skill_rows.py`, verified through `pack_skill_descriptors`). The renderer importer never emits `null` (booleans are computed from frontmatter strings); `parseFlag` documents that a present `null` on a stored row is the backend normalizer's job.
- **P4 — importer parity.** `src/SERVICEs/skill_frontmatter.js` is a faithful port of Unchain's frontmatter parser (block scalars, nested maps/lists, comments, duplicate critical keys) with the Unchain fixtures copied under `src/SERVICEs/__fixtures__/skills/`; canonical-name collisions are no longer skipped at import (the backend resolves them).
- **P5 — CLOSED admission.** `applySkillInventory` validates exact key sets/types (top level, entries, diagnostics, revision pattern); Electron `getMisoSkillInventoryPayload` throws on unknown keys / wrong types instead of defaulting.
- **Refresh gap.** `startSkillInventorySync` re-fetches on `runtime` settings changes (workspace root, `skills.include_user_dirs`), active-chat / selected-toolkit changes and catalog refresh (debounced).
