# Security dependency refresh

Baseline: `dbf055d4b71e2a6a7d7844df1490d5357bc4b44b` (`dev`). This work updates vulnerable JavaScript owners and their locked closures, preserves the existing release/update/signing contracts, and replaces the unsupported Markdown parser. It does not change the Unchain protocol or run provider/model inference.

## Boundaries and acceptance

- **BC-DEP-001 (VERSIONED):** npm registry tarballs and `package-lock.json` produce the installed Electron/CRA/build-tool tree. Electron is pinned to the supported 43.8.3 line; the official native ZIP extractor to 1.0.6; builder to 26.15.3; CI and development require Node 24.22.1 or newer 24.x. Owner overrides retain CRA 5 while upgrading its development server, SVG loader, URL loader, serializer and CSS selector parser. Removed `react-spring` native peer closure is replaced by its web package with the same imported hooks. Unknown exact versions/source bytes fail installation for locally patched packages. **AC-DEP-001:** a clean install, syntax/import checks, full frontend/Electron suites, web build, and existing release QA tests; a real loopback WDS instance must serve legitimate local output and deny malicious Host and cross-origin internal requests.
- **BC-DEP-002 (CLOSED):** pinned MCP runtime archives/wheels enter `extractArchive`/`extractWheel` through the official Electron extractor. Source download identity and SHA-256 verification remain unchanged. **AC-DEP-002:** actual ZIP extraction and wheel extraction preserve a valid Python file, reject parent traversal, mixed separator traversal and an absolute symlink followed by a write, and leave the outside sentinel absent. Existing manifest, atomic staging, sealing and failed-stage tests remain required.
- **BC-DEP-003 (VERSIONED):** app-builder-lib's real macOS producer creates `/usr/bin/security` argument arrays. The known password bug still exists in 26.15.3; an exact version + SHA-256 patch separates P12 passwords from the random temporary keychain password. No signing bypass is added. **AC-DEP-003:** execute actual original and patched dependency code against a strict command consumer with different application, installer and keychain passwords; import failure must still reject; changed/partial bytes must fail closed. Actual signed release qualification remains the protected release workflow's responsibility.
- **BC-DEP-004 (VERSIONED):** known unpatched upstream `braces` 3.0.3 and `sprintf-js` 1.1.3 receive exact source-digest patches at installation. All installed copies named by the lock are covered, including nested copies. Braces parser and every recursive AST walker reject nesting/cycles before recursion; ordinary quoted/nested glob patterns remain supported. Sprintf bounds native numeric precision (including zero significant digits) and padding; unsupported uppercase E/G conversions retain their existing rejection. **AC-DEP-004:** original code reproduces stack exhaustion/native precision errors; patched string and direct/forged AST paths are bounded; nested installed copies, repeat installation, unknown versions, changed bytes and partial patches are tested. These local fixes do not alter npm advisory metadata or suppress audit results. The public audit can continue reporting the no-upstream-release braces advisory even though installed source is patched.
- **BC-DEP-005 (OPEN/strict sanitization):** untrusted Markdown text enters markdown-it 15.0.3 with task-list support; parser-produced HTML enters DOMPurify 3.4.17 and a React DOM adapter. The adapter retains fenced-code/pre rendering, think containers, tables, task lists and links while dropping active HTML, events, dangerous URLs and unsupported attribute names. **AC-DEP-005:** dedicated Markdown security/compatibility tests, chat streaming/serializer tests, web production compilation and isolated actual Chromium renderer proof. No provider access or model inference is used for this proof.

BC-DEP-004 filesystem identity: a new guard is created exclusively without replacing an existing file; an existing guard is verified through a read-only, no-follow regular-file descriptor. Source digest checks and writes share one verified descriptor, use explicit-position complete writes, and truncate only after verification and write completion. Path identity changes, symbolic/nonregular files, missing metadata in a present package and zero-progress writes fail closed; only an entirely absent dependency may be skipped. AC-DEP-004 includes native filesystem racer, symlink, FIFO, short-write, metadata-disappearance and repeat-install controls in `dependency-install-race.test.mjs`.

## State sequences

- **SEQ-DEP-001:** clean locked install → bounded patches → tests/build → repeat postinstall. The repeat must be byte-identical; modified upstream source or unreviewed versions must stop installation. Maps to BC-DEP-001/003/004 and AC-DEP-001/003/004.
- **SEQ-DEP-002:** existing sealed MCP stage → invalid archive or failed extraction → previous stage preserved → valid archive → atomic replacement. Cache retry rechecks source SHA-256; unchanged runtime manifest/pins remain the canonical staging identity. Maps to BC-DEP-002 and AC-DEP-002.
- **SEQ-DEP-003:** development server cold start → local asset → malicious Host → malicious Origin/internal endpoint → legitimate local asset → stop. Forbidden requests must not mutate/invalidate the server; local operation continues. Maps to BC-DEP-001 and AC-DEP-001.
- **SEQ-DEP-004:** Markdown streamed chunks → complete document → rerender and table/task/code interactions. Sanitization applies on each render and cannot be bypassed by the custom pre/think components. Maps to BC-DEP-005 and AC-DEP-005.

Chat normal/graph/subagent interaction, retry and durable replay state transitions are not changed here. No Python sidecar module, runtime manifest or serialized provider wire is changed by this JavaScript dependency work. Exact signed installers and restart updates must still pass their protected release qualification on the same release wheel; this PR does not claim that a local Node build constitutes installer certification.

## Upstream embedded Node residual

Electron 43.8.3 is the narrowest currently supported release line; 42.x is end of support. Its official DEPS pins Node 24.22.0, and its Node patch list does not contain the October 21 hostname-normalization or Brotli security fixes from Node 24.22.1. The build/CI/runtime-toolchain Node floor does not replace Electron's embedded Node. The actual downloaded Electron binary reports Node 24.22.0/Chromium 150.0.7871.250: all three synthetic fullwidth-digit, ideographic-dot and shortened-IPv4 hostname cases incorrectly accept a DNS-only certificate, while isolated Node 24.22.1 rejects them; normal IP/DNS and mismatch controls behave correctly in both. This confirms an upstream TLS residual, not a completed fix. No network connection or real certificate/key is involved in the control. PuPu Node fetch is predominantly closed-loopback sidecar traffic, with a fixed regex-validated codeload.github.com skill archive URL and fixed-host Ollama HTTPS metadata/download paths. A product path passing an attacker-controlled noncanonical hostname to the vulnerable helper has not been established; do not claim either remote exploitability or blanket unreachability from this binary control. Brotli backport status likewise must not be called fixed without verified upstream source/artifact evidence.

Electron 43 API review: PuPu uses frame:true windows without Window Controls Overlay, has no nativeImage.toBitmap/getBitmap or chrome.scripting use, already supplies explicit dialog default paths, and does not request Linux showHiddenFiles. No application compatibility shim is indicated by these documented 43 changes. Full combined tests and production compilation remain required.
